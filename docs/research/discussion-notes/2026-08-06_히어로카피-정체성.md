# 히어로 카피와 프로젝트 정체성

> ✅ **실제 기록.** 개발 세션에서 실제로 내려진 결정을 사실 그대로 기록한 것이다.

## 논의 배경

전날 랜딩 리디자인(`2e7e830`)으로 히어로 구조는 정리됐으나, 헤드라인 문구 자체는 검토되지 않은 채였다. 당시 문구는 **"모든 펜싱 대회 기록을 한곳에서"**였고, 이에 대해 *"이게 최선인가, 처음 들어온 사람은 어떤 느낌일까"*라는 문제 제기가 있었다.

## 지적된 문제

세 가지가 지적되었다.

1. **주체가 우리 쪽에 있다.** 우리가 가진 것(데이터 규모)을 말할 뿐, 방문자가 여기서 무엇을 얻는지를 말하지 않는다.
2. **"모든"은 과장이다.** 2019년 이전 데이터는 존재하지 않는다(협회가 디지털 결과를 게시하지 않은 시기). 사실이 아닌 표현을 첫 화면에 두는 셈이다.
3. **"A를 한곳에서"는 집계 서비스의 상투구다.** 어떤 분야에 갖다 붙여도 성립하는 문장이라 이 서비스의 성격이 전혀 드러나지 않는다.

## 결정 사항

### 헤드라인

**"이름 하나로 펜싱 기록 전부 확인하세요"**

주어를 서비스에서 사람으로 뒤집되, "펜싱"을 기록에 직접 붙여 어떤 분야의 서비스인지가 문장 안에서 드러나게 했다.

### 히어로 통계 지표

**"종목 2,968" → "경기 51,848"**로 교체했다.

일반 방문자에게 "종목"은 플뢰레·에페·사브르 세 가지로 읽힌다. 그 상태에서 2,968이라는 숫자가 붙으면 단어와 숫자가 서로 맞지 않아 오히려 신뢰를 깎는다. "경기"는 별도 설명 없이 이해되고, 51,848이라는 규모가 그대로 전달된다.

## 결정 근거

세 지적 모두 "방문자가 첫 화면에서 무엇을 이해하는가"라는 같은 기준에서 나왔다. 헤드라인은 방문자가 할 수 있는 행동("이름 하나로 확인")을 말하도록, 통계는 설명 없이 읽히는 단위를 쓰도록 각각 바꾼 것이다. 과장(2번 지적)을 없앤 것은 데이터 정확성을 서비스의 핵심 가치로 두는 프로젝트 원칙과도 일치한다.

## 이 논의에서 명문화된 것

프로젝트 정체성이 이 논의를 계기로 문장으로 정리되었다.

> **"펜싱 선수 아빠가 딸을 위해 만들었다"**

이전까지 이 성격은 ID 체계(`KOP00000` = 박소윤을 시스템 기준점으로 부여) 같은 구현 흔적으로만 남아 있었고, 문서에 문장으로 기록된 것은 이 시점이 처음이다.

## 남은 쟁점

- 정체성 문장을 화면(히어로·소개 영역)에 노출할지 여부 — 이 논의에서 결론 없음
- 7개 언어 번역본에서 새 헤드라인이 같은 효과를 내는지 — 이 노트 작성 시점 기준 검증 기록 없음
