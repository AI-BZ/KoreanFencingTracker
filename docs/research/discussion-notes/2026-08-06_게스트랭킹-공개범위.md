# 비로그인 사용자에게 랭킹이 과다 노출된 문제

> ✅ **실제 기록.** 개발 세션에서 실제로 발견·수정된 문제를 사실 그대로 기록한 것이다.

## 문제 발견 경위

사용자가 **"로그인 안 했을 때 11위부터 다 보인다"**고 지적했다. 설계 의도는 비로그인 상태에서 상위 일부만 실명 노출하고 나머지는 블러 처리하는 것이었으나, 실제 화면은 그렇게 동작하지 않았다.

## 실측 결과

| 확인 항목 | 실제 상태 |
|-----------|-----------|
| 블러 적용 범위 | 1페이지의 앞 10개 **항목**에만 적용. 순위(rank) 값은 보지 않고 있었음 |
| 2페이지 이후 | 블러 **0건** |
| 노출 규모 | 118명 중 **108명 실명 노출** |

## 원인

두 곳이 함께 작용했다.

1. `blur_ranking_entries()`가 **리스트 인덱스 기준**으로 블러 대상을 판정했다. 순위가 아니라 "화면에 몇 번째로 그려지는가"를 기준으로 삼은 것이다.
2. 호출부에 `start == 0` 조건이 있어, 2페이지 이후(`start > 0`)에는 블러 함수 자체가 실행되지 않았다.

두 번째가 없었더라도 첫 번째 때문에 페이지마다 앞 10개가 블러되는 잘못된 동작이 남았을 것이다. 인덱스와 순위를 같은 것으로 취급한 것이 근본 원인이다.

## 결정 사항

1. **판정 기준을 인덱스에서 순위(rank)로 변경.** 페이지네이션 위치와 무관하게 순위 값으로 블러 여부를 결정한다.
2. **공개 임계값을 상위 10위에서 상위 30위로 확대.** (사용자 결정)

## 결정 근거

(1)은 버그 수정이다. 인덱스 기준으로는 페이지를 넘길 때마다 판정이 어긋나므로 순위 기준이 유일하게 올바른 방식이다.

(2)는 정책 변경으로, 사용자가 결정했다. 임계값 선택의 구체적 근거는 이 세션 기록에 남아 있지 않다. `[기록 없음]`

## 남은 쟁점

- 상위 30위라는 수치의 근거 — 기록 없음. 이후 사용 데이터로 재검토 여지 있음
