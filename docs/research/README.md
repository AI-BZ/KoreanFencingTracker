## 🔴 작성 원칙 (제출용 문서이므로 반드시 지킬 것)

보고서로 제출되는 문서다. 아래를 어기면 자료 전체의 신뢰도가 무너진다.

1. **없었던 논의를 만들어내지 않는다.** 디스커션 노트는 **실제로 오간 대화만** 기록한다. 기억이 흐릿하면 "정확한 날짜 불명"이라고 쓰고 넘어간다. 소급해서 그럴듯한 대화를 창작하는 것이 가장 위험하다.
2. **재구성한 것은 재구성이라고 밝힌다.** PRD처럼 사후에 복원한 문서는 제목과 본문에 명시하고, 무엇을 근거로 복원했는지(커밋 해시, 코드 위치, 대화 기록) 출처를 단다.
3. **추정과 사실을 구분한다.** 근거가 있는 것은 출처를 달고, 추정은 "추정"이라고 표기한다.
4. **날짜는 검증 가능한 것을 쓴다.** git 커밋 날짜, 파일 수정 시각, 대회 일정 등 확인 가능한 근거 우선.
5. **노트는 논의 직후에 쓴다.** 몇 달치를 몰아서 채우면 그건 기록이 아니라 창작이다.

## 디스커션 노트를 남기는 시점

- **시작 단계** — 무엇을 왜 만들기로 했는가
- **제작 후** — 만들어보니 어땠는가, 처음 가정과 무엇이 달랐는가
- **이슈 해결** — 문제 발견 경위, 원인, 선택지, 왜 그 해결책을 골랐는가
- **중요 변경** — 방향을 바꾼 결정과 그 근거

## 노트 유형 구분 (혼동 금지)

| 유형 | 참여자 | 표기 |
|------|--------|------|
| **공동연구 논의** | 박계진 ↔ 박소윤 | `participants: 박계진, 박소윤` |
| **AI 협업 세션 결정** | 박계진 ↔ Claude (개발 도구) | `participants: 박계진, Claude (개발 보조)` |

두 가지는 성격이 다르다. 공동연구자와의 도메인 논의(펜싱 규칙, 선수·학부모 관점 검증)와, 개발 도구를 쓰며 내린 구현 결정을 같은 것처럼 섞어 쓰지 않는다.
