## 1. 문제 정의

### 1.1 배경
대한펜싱협회(fencing.sports.or.kr)가 대회 결과를 공시하지만, 실사용자 관점에서 다음이 불가능했다. `[추정 — 다만 아래 1.2의 구현된 기능들이 이 문제들의 해결책이라는 점이 방증]`

- **선수 단위 조회 불가**: 대회별로 결과가 흩어져 있어 "한 선수의 기록 전체"를 볼 수 없음
- **누적 추적 불가**: 시즌 성적 추이, 랭킹 변동을 알 수 없음
- **상대 전적 부재**: 특정 상대와의 과거 대결 기록 조회 불가
- **접근성**: 대회장에서 모바일로 즉시 확인하기 어려움

### 1.2 해결하려는 사용자 과제
| 사용자 | 실제 상황 | 필요 |
|--------|-----------|------|
| **학부모** (1차 사용자) | 대회장/귀가 후 "우리 애 몇 등이지?" | 선수명 검색 → 즉시 결과 |
| **선수** | 다음 상대가 정해짐 | 상대 전적, 상대 최근 성적 |
| **코치** | 소속 선수 다수 관리 | 팀 단위 조회, 성과 추이 |

출처: 프로젝트 정체성 정의(`CLAUDE.md` — "펜싱 선수 아빠가 딸을 위해 만들었다"), H2H 기능 구현(2026-05), 클럽 관리 기능(2025-12-23 커밋 `Fix homonym identification and add club management features`).

### 1.3 프로젝트 기원
개발자 본인이 펜싱 선수(박소윤)의 학부모로서 겪은 불편에서 출발. 시스템 ID 체계에서 박소윤에게 `KOP00000`을 부여해 기준점으로 삼은 것이 이를 뒷받침한다. 출처: `CLAUDE.md` ID System 절 — "특별 ID: KOP00000 = 박소윤(최병철펜싱클럽) - 시스템 기준점".

## 2. 요구사항

### 2.1 데이터 요구사항 (가장 강한 제약)
프로젝트 규칙 문서에 "제1원칙"으로 명문화되어 있다. 출처: `CLAUDE.md`.

- **단일 진실 원천**: 협회 공식 데이터가 진실. 자체 계산은 공식 순위 미게시 시에만 임시 사용하고 출처를 표시
- **파이프라인 전파**: 한 곳의 수정이 관련 데이터 전체에 자동 반영
- **데이터 무결성 불변식**:
  - 성별 불변 (남↔여 전환 불가 — 다른 사람)
  - 나이그룹 단조 진행 (역행 불가)
  - 무기 일관성 (2개 이상이면 동명이인 의심)
- **수집 완결성**: Pool + DE 대진표 + 최종순위를 **한 세트로** 수집. 부분 수집은 불완전 데이터로 간주
- **수집 범위**: 2019년 이후. 그 이전은 디지털 결과가 존재하지 않음(텍스트 공지만)

## 3. 데이터 아키텍처 결정

### 3.1 수집 (Acquisition)
- **방식**: Playwright 기반 브라우저 자동화. 대상 사이트가 JavaScript 상태에 의존해 **URL 직접 접근이 불가하고 클릭 네비게이션만 가능**하기 때문. 출처: `CLAUDE.md` Important Notes
- **자동화**: 스케줄러(`run_scheduler.py --multichannel`)가 주기 수집 + 변경 감지 + Discord 알림
- **스크래퍼 단일화 원칙**: `full_scraper.py` 하나만 유지, 대회별 임시 스크래퍼는 사용 후 `backup/`으로 이동

### 3.2 저장 (Storage)
- **Supabase (PostgreSQL)** 채택. JSON 파일 기반은 명시적으로 금지됨(`CLAUDE.md` 데이터 소스 규칙)
- **테이블 네이밍**: 공유 테이블은 접두사 없음(`members`, `players`), 도메인 전용은 `{domain}_` 접두사. 6개 서브도메인 간 merge 충돌 방지 목적

### 3.3 랭킹 산정 규칙 (도메인 지식이 가장 많이 들어간 영역)
- 엄격한 연도 기반 (롤링 윈도우 금지)
- **자유 참가 원칙**: 시도별 선발 등 참가 기회가 제한된 대회(전국체전·소년체전)는 포인트 제외, 결과는 표시
- 유소년/청소년 국가대표 선발전은 랭킹 완전 제외 (일반 국대선발과 다른 대회)
- 2카드 시스템: 나이리그 랭킹 + NT 전체 랭킹 병행 표시
- 포인트 공식: `base_points × prestige × rank_ratio × age_weight`, Best N 가중합

이 규칙들은 코드보다 **도메인 이해**가 선행되어야 하는 영역으로, 공동연구자(현역 선수)의 검증이 필요했던 부분이다. `[추정 — 구체적 논의 기록 없음]`
